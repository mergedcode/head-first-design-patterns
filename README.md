# Head First Design Patterns - Practice Repository

A practical, code-first repository implementing design patterns and Low-Level Design (LLD) based on **_Head First Design Patterns (2nd Edition)_** by Eric Freeman and Elisabeth Robson.

---

## 🎯 Objective
- Write maintainable, extensible, and loosely-coupled object-oriented software.
- Master SOLID design principles.
- Implement design patterns from scratch through real-world scenarios.

---

## 📐 SOLID Principles Checklist
- [x] **S - Single Responsibility Principle:** A class should have one, and only one, reason to change.
- [x] **O - Open/Closed Principle:** Software entities should be open for extension, closed for modification.
- [x] **L - Liskov Substitution Principle:** Subtypes must be substitutable for their base types.
- [x] **I - Interface Segregation Principle:** Clients should not be forced to depend on interfaces they do not use.
- [x] **D - Dependency Inversion Principle:** Depend on abstractions, not on concretions.

---

## 📂 Design Patterns Catalog

### 1. Creational Patterns
- [ ] **Factory Method** - Decouple object creation logic from client code.
- [ ] **Abstract Factory** - Create families of related or dependent objects.
- [ ] **Singleton** - Ensure a single class instance with a global access point.
- [ ] **Builder** - Construct complex objects step-by-step.
- [ ] **Prototype** - Clone existing objects without depending on their concrete classes.

### 2. Structural Patterns
- [ ] **Adapter** - Convert incompatible interfaces to allow collaboration.
- [ ] **Decorator** - Attach new behaviors to objects dynamically.
- [ ] **Facade** - Provide a simplified interface to a complex subsystem.
- [ ] **Proxy** - Provide a surrogate or placeholder to control access to an object.
- [ ] **Composite** - Compose objects into tree structures to represent part-whole hierarchies.

### 3. Behavioral Patterns
- [ ] **Strategy** - Define a family of interchangeable algorithms.
- [ ] **Observer** - Notify multiple subscriber objects about events.
- [ ] **Command** - Encapsulate requests as objects (enables undo/redo, queues).
- [ ] **State** - Alter object behavior when its internal state changes.
- [ ] **Template Method** - Define algorithm skeleton, deferring steps to subclasses.
- [ ] **Chain of Responsibility** - Pass requests along a chain of handlers.
